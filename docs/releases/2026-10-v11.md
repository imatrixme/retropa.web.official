# 2026-10 v11 记录：更新日志与 2.4 外观章节

## 状态

本地实现，**未部署**。修订号 `channel-surf-2026-10-v11`，对应 OpenSpec change `update-official-website-for-2-4`（父仓库）。部署、Nginx 改动和 Search Console 提交都需要用户另行授权。

## 变更

- **更新日志** `/changelog/`（英、简中、日）：按 2.4 → 1.0 版本线分组，从新到旧排列。功能版本逐条列出，维护版本只写一行。月份取自各构建提交 App Store 的时间，页面注明是大致月份。首页首屏新增 “What's new in {版本}” 入口，页脚加入链接。首页 SoftwareApplication 补充 `softwareVersion` 和 `releaseNotes`。
- **App 发布闸门**：`src/content/releases.ts` 的 `releasedVersion`（当前 `2.3.2`）决定网站描述到哪个版本。2.4 的内容都跟随它：更新日志条目、首页外观章节、featureList，以及 89 个带 `release: "2.4.0"` 的媒体文件。2.4 上架前这些内容不发布：构建会从 `dist/` 删除这些文件，任何页面引用它们即失败。用 `VITE_APP_VERSION=2.4.0` 可以预览。
- **2.4 外观章节**（随 2.4 上线）：8 个系列共 44 款外壳，使用原生单选按钮做选择器；质感 × 光泽 3×3 对照图；4 套 PRO 键帽。窄屏时色板改为大图正下方的一条横向色板带，选中后变化始终在视野内。
- **品牌短片段落**：已实现，但**不会发布**。片中画面出现 Wonkie Guy，而它没有可用的许可证。清单的 `gameplay` 字段要求逐款游戏写明许可证，媒体闸门会点名拦截这类文件。海报在接近视口时才加载，不与首屏争抢带宽。
- **agent 可读层**：已实现，但**暂时隐藏**（用户 2026-10-06：“AI相关先隐藏”）。`src/lib/site-config.ts` 的 `agentReadable` 为 `false`，构建不发布下面任何一项，`robots.txt` 与 v10 相同；完整性检查和 HTTP 证据会确认它们都不存在。开启后：
  - 构建往 `dist/robots.txt` 写入 Content Signals：`search=yes, ai-input=yes`。`ai-train` 不声明，即既不授权也不限制。
  - 每个可索引页旁生成 `index.md`，页面用 `<link rel="alternate" type="text/markdown">` 声明它；另提供 `/llms.txt`。
  - 请求的 `Accept` 包含 `text/markdown` 时，同一 URL 返回 Markdown，并附 `Vary: Accept` 和指回 HTML 的 canonical `Link`。预览服务器按构建证据里的开关决定是否协商，生产规则在 `deploy/nginx-agent-readable.conf.example`。
  - HTTP 证据脚本按开关检查：开启时检查协商，关闭时检查 `Accept: text/markdown` 拿到的是 HTML、`/llms.txt` 返回 404。
- **设计精修**：展示字宽 118% → 108%，字重 800 → 760。去掉标题与 eyebrow 的辉光，按钮辉光减弱。超大标题缩小 15–20%，背景描边字与光晕变淡。更新日志的版本索引在窄屏改为一行横向滚动。

## 2.4 上线清单

1. 2.4.0 在 App Store 上架后，把 `releasedVersion` 改为 `"2.4.0"`，并核对 2.4.0 条目的月份。
2. 短片二选一：用有许可证的游戏（如 Metal Warrior 4）重渲染，或取得 Wonkie Guy 作者的书面许可。之后把视频和海报放进 `public/media/film/`，清单条目写 `release: "2.4.0"`，并在 `gameplay` 中逐款写明许可证。不放入时，短片段落不会出现。
3. 运行 `bun run lint`、`bun run build`、`bun run snapshot`、`bun run evidence`、`bun run evidence:http --base http://127.0.0.1:4178`。
4. 经授权后发布：按 v10 流程把 `dist/` 发布为新的 release 并原子切换软链接。
5. Nginx 不用改：agent 层隐藏时，`deploy/nginx.conf.example`（与 v10 相同）就够了。发布后运行 `bun run evidence:http --base https://retropa.com`。
6. 经授权后在 Search Console 重新提交 sitemap（新增 3 个更新日志 URL）。

## 开启 agent 可读层时

1. 把 `src/lib/site-config.ts` 的 `agentReadable` 改为 `true`，再跑上面第 3 步的全部检查。
2. 经授权后合入 `deploy/nginx-agent-readable.conf.example`：`map` 放进 `http {}`，四个 location 放进 retropa.com 的 server 块。先 `nginx -t` 再 reload，并与开启后的构建在同一次发布中上线，然后运行 `bun run evidence:http --base https://retropa.com`。
3. 用 isitagentready 复扫，确认 Content Signals、Markdown 协商和 llms.txt 都被识别。
4. 如需对 AI 训练表态，只改 `scripts/agent-assets.ts` 中的 `contentSignal`。

## 暂缓

- 外观章节没有挂 `data-feature` 埋点：现行分析契约的 `feature_id` 不包含 looks。要挂埋点，先改契约。
- 无 JS 时，短片播放器没有海报：浏览器会在空的 `<video>` 上画一层灰色占位，CSS 背景图被盖住。播放功能不受影响。
